# M10 UI inventory and integration audit

Reviewed 2026-10-24 from `develop` at `d03d873` (M9 merged). This is a source and serialized-scene audit, not a live UI or multiplayer test. The [cinematic revision](DESIGN_SYSTEM.md) is the current visual proposal; its PNGs and editable Figma menu/lobby are not screenshots of Unity.

| Surface | Existing source and behavior | Main UX gap | State to consume during implementation |
| --- | --- | --- | --- |
| Main Menu | `MainMenu.unity` has a uGUI Canvas, TMP title/subtitle, Host Game, Join Game, join-code input, and status. `MultiplayerSessionController` handles host/join. | No separate Profile, Settings, or Quit actions; fixed center placements and flat visual treatment. Host/join dominates without a clear navigation hierarchy. | Preserve the controller's existing host/join paths and status/error text; add navigation presenters and functional actions. |

Session `Changed` also refreshes at 0.25 s intervals. | Combat HUD | `FirstPersonPlayer.prefab` has a separate uGUI Canvas with health, ammo, crosshair, hit confirmation, death message and damage flash. Rifle fire/reload already requires a locked cursor. | Plain text metrics, no teammate health/name strip, and no shared visual states for warning/critical/reloading. | `PlayerHealth`, `AutomaticRifle`/`NetworkRifle`, `NetworkPlayer`, replicated player health, current weapon state. | Danger zone | `FirstPersonTest.unity` has `EncounterHud` with warning/progress TMP labels; it subscribes to `DangerZone.Changed` and hides a clear notice after four seconds. | Large text switches without a designed warning-to-compact-tracker transition or consistent success styling. | Existing replicated `DangerZone` state, name, wave count and remaining enemies. |

| Results | `MissionHud` builds rank, score, duration, score breakdown, per-player/TEAM rows, local XP and unlock text. ## Existing assets and technical constraints

- Runtime UI is uGUI with TextMesh Pro. The menu scene has one `EventSystem` using `InputSystemUIInputModule`; the major canvases use 1920 × 1080 `CanvasScaler` references. No runtime UXML/USS was found.
- The bundled Liberation Sans SDF is the only UI font recorded in `ASSET_LICENSES.md`. The new review renders use macOS system DIN Condensed and Avenir Next as concept typography; no font file is imported. Importing a distributable font into Unity requires approval and a license entry.
- The research facility art is approved for the map and could supply a live menu backdrop if a cheap camera view is practical. The new Stage A backdrops are original generated concept images outside Unity, not approved game assets. The earlier Figma vector backdrops are archived with the first visual pass.
- Existing `session.Players` UI shows numbered slots, not verified display names. Ready-state data is absent. Stage B needs a small compatible session/player property design before those elements become functional.
- Four separate UI controllers/canvases currently cover menu, player HUD, encounter HUD, and mission/results. Shared styles should be built as uGUI prefabs/theme data while presentation consumes existing state. A broad UI Toolkit migration would add risk without solving missing data or layout behavior.

## Functional gaps requiring implementation and live validation

1. Host/join errors, session removal, connecting/loading, and invalid actions must remain visible after the redesign.
2. The lobby's ready/display-name proposal needs a clear data source and multiplayer tests; a purely local badge would be misleading.
3. The profile mockup shows existing M9 statistics and cosmetic choices; no additional weapon or inventory is proposed.
4. UI focus must prevent movement, firing and look input while typing or interacting with menu controls. The current locked-cursor guard covers rifle fire, but the pause/input flow needs a full test.
5. The results screen mockup uses illustrative numbers. Runtime values must come from the existing score and progression systems.
6. Captures of the current Unity screens and after-implementation screens, 720p/1080p/1440p/16:10 checks, two-client lobby/gameplay checks, compilation and UI profiling belong to Stages B–F. None are claimed by this design audit.
